
# Чекліст готовності зовнішніх залежностей

Проєкт: Сервіс бронювання аудиторій і обладнання з погодженням заявок.

Джерело рішення: ретроспектива ЛР3, картка F-001.

## 1. Правила перевірки залежностей

Перед включенням історії із зовнішньою інтеграцією
до спринта необхідно перевірити:

- [ ] Визначено відповідального за зовнішню систему.
- [ ] Відомий канал зв'язку з відповідальним.
- [ ] Підтверджено доступ до тестового середовища.
- [ ] Отримано необхідну API-документацію.
- [ ] Узгоджено строк отримання відповіді.
- [ ] Перевірено основний інтеграційний сценарій.

## 2. Застосування до історії S-09

Історія: Автоматичне отримання зайнятості
аудиторій із розкладу занять.

| Перевірка | Стан |
| --- | --- |
| Відповідальний за інтеграцію | Не підтверджено |
| Канал зв'язку | Не підтверджено |
| Доступ до тестового середовища | Не підтверджено |
| API-документація | Не підтверджено |
| Дата відповіді | Не підтверджено |
| Інтеграційний тест | Не виконано |

## 3. Рішення щодо готовності

Статус S-09: Not Ready.

Історію не можна вважати готовою до реалізації,
доки не підтверджено критичні зовнішні залежності.

Непідтверджені значення не означають, що доступу
немає: вони означають, що доказів готовності ще
не отримано.

## 4. Правило для наступних спринтів

Перед Sprint Planning перевіряється цей чекліст.

Якщо зовнішня залежність не готова, історія
залишається в Product Backlog.

Для розблокування створюється окреме завдання
із зазначенням відповідального та наступної дії.
