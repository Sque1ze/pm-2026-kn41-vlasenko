## 1. Definition of Workflow

Для управління роботою використовую Kanban-дошку GitHub Projects. Спочатку створено 12 завдань F-001–F-012, а після другого конверта додано термінову картку F-013.

Мета дошки — візуалізувати виконання завдань, обмежувати одночасну роботу, виявляти блокування та вимірювати швидкість потоку.

| Колонка | Умови входу | Умови виходу |
| --- | --- | --- |
| Backlog | Є ключ, назва, опис і результат завдання. | Уточнено обсяг, критерії завершення та залежності. |
| Ready | Завдання зрозуміле, підготовлене й може бути виконане за 1–2 дні. | Виконавець починає роботу за наявності вільного WIP-слота. |
| In progress | Фактично розпочато роботу, записано дату початку. | Підготовлено результат для перевірки. |
| Review | Результат доступний, критерії завершення можна перевірити. | Результат прийнято або повернуто на доопрацювання. |
| Done | Критерії виконано, результат перевірено, дату завершення зафіксовано. | Картка залишається як історичний запис. |

Для кожної картки фіксуються ключ, тип, дати створення, початку й завершення, блокування та посилання на результат.

**Cycle time = дата завершення − дата початку роботи.**

Розрахунок здійснюється у календарних днях. Якщо завдання почалося й завершилося одного дня, cycle time дорівнює 0.

Час у Backlog і Ready до фактичного початку роботи не входить до cycle time.

### Що роблю, коли ліміт вичерпано

Якщо в In progress перебувають дві картки, третю не починаю, поки не звільниться місце.

Якщо Review містить дві картки, спочатку завершую перевірку однієї з них.

Заблокована картка залишається незавершеною. Причину блокування та необхідні дії потрібно зафіксувати.

Основний принцип — **завершувати розпочату роботу перед початком нової**.

### Коли ліміт спрацював

2026-11-08 за конвертом 1 WIP In progress зменшено з 3 до 2.

На момент зміни в In progress було 0 карток, тому негайного обмеження потоку не виникло.

Надалі завдання виконувалися послідовно. За наявними спостереженнями не підтверджено випадку, коли нове завдання чекало саме через заповнений WIP.

Підсумкову перевірку умови конверта, зокрема спостереження протягом щонайменше двох днів, необхідно завершити окремо.
